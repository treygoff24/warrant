## The undo and compensation interfaces that exist

Atlas has one `undo` tool and a registry of compensations keyed by event kind. The paths below are the definitions at the pin.

| Path | Verified interface |
| --- | --- |
| `packages/core/src/contracts/tools.ts:42` | `Compensation`, an asynchronous function over the database transaction, recorded event, and request context |
| `packages/core/src/actions/tools.ts:32` | `registerActionCompensations`; the same file's `actionsTools` module defines `undo` at line 57 |
| `packages/core/src/tools/create-registry.ts:9` | `createRegistry`, which rejects duplicate tool and compensation names and installs the compensation map read by `undo` |
| `packages/core/src/tools/registry.ts:25` | The composed actions, graph, campaign, and correspondence inventory |
| `packages/core/src/campaign/compensations.ts:96` | `campaignCompensations`, backed by `undoObjective`, `undoStance`, `undoStakeholder`, `undoPathway`, and `undoWorkItem` |
| `packages/core/src/graph/compensations.ts:112` | `graphCompensations`, backed by `undoPersonUpsert`, `undoMembershipSet`, `undoRelationshipLink`, and `undoNoteAdded` |

The `undo` tool locks the event row, finds the compensation for the event kind, runs it in the transaction, and records `event_reverted`.

The compensation functions refuse a stale undo when later work touched the same subject. The campaign functions also check row versions where the subject carries one. Several creations and destructive operations are deliberately irreversible.

## The transports section 1.7 points toward

The registry has three projections:

1. AI SDK: `packages/core/src/tools/to-ai-sdk.ts:10` exports `toAiSdkTool`. `apps/worker/tools.ts:44` accepts a projection when it binds durable tool steps. At this pin, no checked-in production composition connects the core projection and the composed registry in the worker; the projection is covered directly by core tests.
2. MCP: `packages/core/src/tools/to-mcp.ts:70` exports `toMcpTool`. `apps/web/src/auth/mcp.ts:76` builds the server from the composed registry and projects every definition.
3. CLI: `packages/core/src/tools/to-cli.ts:228` describes each subcommand. `apps/cli/src/main.ts:39` builds the command table from every registry definition and sends calls to the instance over HTTP.

Atlas also uses Next.js App Router file-system routes under `apps/web/app/`. The manifest records Next.js 16.3.4, so W1.8 needs the Next.js adapter. DBOS is a workflow framework, not a file-system route adapter, but it remains in the manifest because it changes how the worker executes tool calls.

## What section 1.7 was illustrating

The phrases "grouped undo in a meeting debrief" and "a second undo dispatcher" are acceptance-story names, not names found in this tree. `record_debrief` appears in `packages/core/src/tools/registry.ts` only in the list of unfinished tools that are deliberately absent from the registry. No grouped-debrief compensation exists at this pin. The actual reuse candidate is the `undo` tool, its installed compensation map, and the two exported compensation registries described above.
